
** Call Container

**** Preface

To note, initially we just juggled two iframes that way we could allow Element Call to handle
the lobby behavior.
Then we transitioned to a livekit base in which we customized the look and feel of.

However, now we don't use Element call at all nor Livekit in the core app.
Instead we load a driver from the engine and it maps to our functions and provides the
functionality to our call interface.
This means that regardless of protocol as long as the engine tells us how to map
to their call spec then Paradise can just 'work' for their calls.

**** Code

To note, initially we just juggled two iframes that way we could allow Element Call to handle
the lobby behavior. However, given we have full control over the UI now we can easily create
that experience with just a single top level container.

#+begin_src clojurescript :tangle ../../../../../src/paradise/ui/container/call/call_container.cljs
(defn persistent-call-container [children]
  (let [call-state @(rf/subscribe [:call/state])
        deafened?  @(rf/subscribe [:call/deafened?])
        {:keys [status livekit-token livekit-url]} call-state]
    [:div.persistent-call-host
     {:style {:width "100%" :height "100%"}}

     (if (and livekit-url livekit-token)
       [:> (.-LiveKitRoom lk)
        {:video false
         :audio false
         :token livekit-token
         :serverUrl livekit-url
         :options (rtc/get-lk-options)
         :onError (fn [err] (js/console.error "LIVEKIT ERROR:" err))
         :onDisconnected (fn [reason] (rf/dispatch [:call/livekit-disconnected reason]))}

        [:> custom-call-stage]
        [:> (.-RoomAudioRenderer lk) {:muted deafened?}]
        children]
       children)]))
#+end_src
